# Как добавить новый источник (30-60 минут)

## 1. Разведка (10 мин)

Открой сайт в браузере, DevTools -> Network -> Fetch/XHR, полистай каталог.

- **Есть JSON-запрос с данными?** Отлично: парси JSON, это надёжнее HTML. В `parse_list`/`parse_item` используй `json.loads(html)`.
- **Данные есть в исходнике страницы (Ctrl+U)?** Обычный HTML-парсинг, как в `books_demo.py`.
- **Данные появляются только после JS и JSON не найти?** Нужен Playwright (`pip install .[browser]`). Это медленнее и дороже - закладывай в цену.

Проверь пагинацию: как меняется URL при переходе на страницу 2 (`?page=2`, `/page-2`, `offset=`).

## 2. Модель (5 мин)

Скопируй `src/pipeline/sources/books_demo.py` в `src/pipeline/sources/<имя>.py`.

Опиши поля в классе-наследнике `Record`:

- поле **без** значения по умолчанию = обязательное (без него строка уйдёт в отбраковку);
- поле `= None` = необязательное (в отчёте будет видна его заполненность);
- `key` - то, что уникально: артикул, id объявления или URL.

Список полей и что обязательно - согласуй с клиентом **до** начала работы. Это и есть критерии приёмки.

## 3. Селекторы (15-30 мин)

- `list_urls` - генератор страниц каталога.
- `parse_list` - ссылки на карточки (абсолютные, через `urljoin`).
- `parse_item` - словарь сырых полей. Очистку цены/дат делай валидатором в модели, не здесь.

## 4. Регистрация

В `src/pipeline/sources/__init__.py` добавь класс в `SOURCES`.

## 5. Тест (10 мин)

Сохрани одну страницу каталога и одну карточку в `tests/fixtures/` (Ctrl+S или `curl -o`). Скопируй тест `test_parse_item_fields` и проверь ключевые поля. Тест не зависит от сети - при смене вёрстки сайта он покажет, что сломалось.

## 6. Образец для клиента

```bash
pipeline run <имя> --limit 50 --out csv xlsx
```

Отправляешь клиенту `.xlsx` + `_report.md`. Это и есть демо на 50 записей.
